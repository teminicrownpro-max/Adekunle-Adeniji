Product sinks

7 / 12

Each sink is a data use case. Together they set the storage and access requirements: how fresh, how complete, in what form, and who may see it. These are requirements, not technology choices.

P1 Guided request submission

Type
Product sink
Consumer
CMACs
Data used
Request details, location, checklists and attachments
Value
More complete requests at first submission; fixes the separate checklists and missing information found in WORTS
Storage and access
Fresh
Current requirements for each request type at submission
Complete
Required fields and documents present before review
Form
Structured fields plus attachments
Who sees
The submitting CMAC and reviewing staff

P2 Connected request visibility

Type
Product sink
Consumer
CMACs
Data used
Status, responsible party, dated updates, next action and history
Value
CMACs understand progress and next steps without searching email or Teams
Storage and access
Fresh
Updated at every status or ownership change
Complete
Every material update linked to the Request ID
Form
One dated history per request
Who sees
Authorized users; proposed: a CMAC sees their own requests

P3 Coordinator hand-off support (proposed)

Type
Product sink
Consumer
Infrastructure staff
Data used
Recorded decisions, ownership changes and outstanding actions
Value
Continuity when responsibility moves between coordinators; the hand-off process still needs client validation
Storage and access
Fresh
At each change of owner
Complete
Earlier decisions kept with the request
Form
Decision and ownership history per request

Furniture Request Coordinators and Furniture Coordinators
